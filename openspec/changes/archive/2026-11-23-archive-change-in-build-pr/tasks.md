# Tasks

- [ ] 1. `factory advance` archives the ticket's change in a commit on the run branch once the review passes, before it scores the risk and opens the pull request; a failed attempt archives nothing. Verified by `tests/build-loop.test.ts`: after a passing review the archive commit is on the branch before the push and the pull request, the risk counts its files, and a failed quality, verify or review attempt leaves the change unarchived.
- [ ] 2. When `openspec archive` fails, `factory advance` opens no pull request, leaves no archive commit, and sends the ticket back to refinement with a question that quotes the CLI's error. Verified by `tests/build-loop.test.ts` with an archive that fails: `exit: sent_back`, the question holds the error, no pull request, and the branch head is the reviewed commit.
- [ ] 3. When no folder, or more than one, under `openspec/changes/` holds the ticket's spec files, `factory advance` archives nothing, opens no pull request, and fails the attempt with the pull-and-commit feedback. Verified by `tests/build-loop.test.ts` for a missing folder and for two matching folders, and by a test that a folder whose `tasks.md` has ticked boxes still matches.
- [ ] 4. The ready gate validates the spec against the canonical specs on main: a `MODIFIED` delta of a canonical requirement passes, a delta that does not apply fails with the CLI's finding, and a project with no canonical specs is validated as today. Verified by `tests/cli-inputs.test.ts` (the canonical specs from main are in the validator's folder when `openspec validate` runs) and `tests/refinement.test.ts` (the gate's findings).
- [ ] 5. The real archive step runs `openspec archive <name>` in the run's worktree and commits only what it changed. Verified by `tests/cli-inputs.test.ts` with a recording command runner: the CLI arguments, the commit, and the reset that leaves no commit when the CLI fails.
